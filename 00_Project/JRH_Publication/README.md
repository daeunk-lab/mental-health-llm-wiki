## 이 저장소는 무엇인가

논문을 쓸 때 AI에게 매번 배경을 다시 설명하지 않기 위한 **근거 파일 모음**입니다.

일반적인 위키가 "읽기 위한 자료"라면, 이 저장소는 **AI가 참조하기 위한 자료**입니다.
그래서 파일마다 역할이 명확히 나뉘어 있고, 서로를 참조합니다.

```
질문:  "Results를 써줘"
        ↓
   근거가 없으면 → 매번 다른 글이 나옴

질문:  "02_OUTLINE.md 구조대로, 00_FACTS.md 수치만 써서 Results를 써줘"
        ↓
   근거가 있으면 → 같은 입력 = 같은 출력 (재현 가능)
```

이 저장소는 그 "근거"를 만드는 곳입니다.

## 핵심 파일 4개

나머지는 부수적입니다. 이 넷이 실제로 작동합니다.

### 1️⃣ `CLAUDE.md` — 작업 규칙

AI가 작업을 시작할 때 가장 먼저 읽는 파일입니다.
연구자 정보, 절대 규칙, 파일 역할, 자주 쓰는 명령이 들어 있습니다.

Claude Code에서는 이 파일이 **자동으로 읽힙니다.**

주요 규칙:
- 수치는 `00_FACTS.md`를 벗어나지 않는다
- 인용은 `03_REFERENCES.md`의 ✅ 문헌만
- em dash 금지, APA 7th
- 불확실하면 "확인 필요"라고 말한다

### 2️⃣ `00_FACTS.md` — 확정 수치

**이 저장소에서 가장 중요한 파일입니다.**

학위논문을 직접 대조해서 확정한 수치만 들어 있습니다.
원고·발표자료·초록 어디에서도 이 파일을 벗어나지 않습니다.

특징적으로, **원본의 오류까지 기록**되어 있습니다.

| 예시 | 내용 |
|---|---|
| 태도 Cohen's d | 학위논문 표에는 −0.52로 적혀 있으나 CI 대조 결과 **0.10이 정확** |
| 표본 흐름 | 56명 신청 → 46명 참여 → 39명 완료 |
| 삭제 결정 항목 | 산술이 맞지 않는 탈락자 비교는 원고에서 제외 |

한 번 확정하면 다시 확인하지 않아도 됩니다.

### 3️⃣ `02_OUTLINE.md` — 논증 설계도

산문이 아니라 **논문의 설계도**입니다.

- 핵심 주장 (한 문장)
- 기여 진술 (So what?)
- 결과 → 주장 연결표
- 섹션별 기능
- 예상 질문과 대응 위치
- 분량 배분
- 집필 순서

문장을 쓰기 전에 논증을 먼저 확정하기 위한 문서입니다.
이게 없으면 서론과 논의가 다른 논문이 됩니다.

### 4️⃣ `05_Prompts/manuscript_prompts.md` — 재사용 프롬프트

매번 같은 설명을 반복하지 않기 위한 프롬프트 8종.

| 프롬프트 | 용도 |
|---|---|
| 섹션 집필 | 설계도·수치·문헌을 근거로 작성 |
| 사실 검증 | 원고 수치를 `00_FACTS.md`와 대조 |
| 인용 검증 | 미검증 문헌 사용 여부 확인 |
| 리뷰어 시뮬레이션 | Major Revision 코멘트 생성 |
| 문체 교정 | SCI Q1 수준 교정 |
| 분량 관리 | 섹션별 단어수 점검 |
| 논증 점검 | 주장과 무관한 문단 탐지 |
| 문헌 검증 | DOI 조회 |

## 사용 방법

### 새 섹션을 쓸 때

```
1. 02_OUTLINE.md에서 해당 섹션의 "기능" 확인
2. 00_FACTS.md에서 인용할 수치 확인
3. 03_REFERENCES.md에서 ✅ 문헌 확인
4. 05_Prompts/의 "섹션 집필" 프롬프트 사용
5. 결과를 04_DRAFT/에 저장
6. Revision_Log.md에 결정사항 1줄 기록
```

### 원고를 검증할 때

```
05_Prompts/의 "사실 검증" + "인용 검증" 프롬프트 사용
→ 00_FACTS.md, 03_REFERENCES.md와 자동 대조
```

### Claude Code를 사용할 때

`CLAUDE.md`가 자동으로 읽히므로 파일을 붙여넣을 필요가 없습니다.

```bash
claude
> 02_OUTLINE.md의 Results 1 항목대로 작성해서
  04_DRAFT/results_1.md에 저장하고 Revision_Log.md에 기록해줘
```

## 설계 원칙

**1. 단일 기준점**
수치는 한 곳에만 존재합니다. `00_FACTS.md`가 틀리면 전부 틀리고,
맞으면 전부 맞습니다.

**2. 검증 없이 인용하지 않음**
학위논문에 실려 있어도 서지정보가 틀릴 수 있습니다.
DOI 확인 전에는 ❓로 표시하고 사용하지 않습니다.

**3. 결정은 기록**
왜 그렇게 정했는지를 `Revision_Log.md`에 남깁니다.
나중에 리뷰어 대응 시 그대로 사용됩니다.

**4. 논증 먼저, 문장 나중**
설계도가 없으면 좋은 문장이 나와도 논문이 어긋납니다.

**5. 재사용 가능하게**
`09_Templates/`의 템플릿은 다음 논문에 그대로 쓰입니다.
두 번째 논문부터 설계 단계가 하루로 줄어듭니다.
